Oui. L’approche actuelle est même un véritable atout pour une future orientation touristique.

## Pourquoi le socle actuel est utile

1. **Le projet raconte le territoire**

Il ne présente pas seulement des bâtiments. Il explique pourquoi les industries se sont installées près d’une rivière, d’une forêt, d’un minerai, d’un bourg ou d’une voie ferrée.

C’est précisément ce qui permet de construire un récit touristique territorial.

2. **Les informations sont vérifiables**

Chaque information est reliée à une source et possède un niveau de confiance. Pour un office de tourisme, cela apporte une crédibilité que n’aurait pas une simple carte collaborative ou décorative.

3. **Le modèle distingue visibilité et accessibilité**

Nous avons déjà prévu de séparer :

- un site visible depuis l’espace public ;
- un site visitable ;
- un site privé ;
- un site inaccessible ;
- un site disparu.

C’est indispensable pour ne pas envoyer les visiteurs sur une propriété privée ou vers un lieu qui n’existe plus.

4. **Le projet peut raconter les sites disparus**

Un lieu disparu peut tout de même avoir un intérêt touristique grâce à :

- une photographie ancienne ;
- un plan ;
- un témoignage ;
- un paysage transformé ;
- un parcours sonore ou narratif.

Le tourisme patrimonial ne dépend donc pas uniquement des bâtiments encore debout.

5. **Les données permettent de créer des parcours**

À terme, nous pourrons composer des itinéraires comme :

- les forges et la métallurgie autour de Domfront et Tinchebray ;
- les industries liées aux vallées et à l’énergie hydraulique ;
- moulins, filatures et papeteries ;
- briqueteries, tuileries et ressources géologiques ;
- patrimoine industriel encore en activité ;
- sites reconvertis ou disparus ;
- patrimoine ferroviaire industriel.

## Ce qu’il faudra ajouter plus tard

Le socle patrimonial ne suffira pas à produire directement une offre touristique. Il faudra ajouter une couche spécifique contenant :

- conditions de visite ;
- horaires et tarifs ;
- coordonnées de l’organisme gestionnaire ;
- accessibilité pour les différents publics ;
- stationnement et transports ;
- durée conseillée ;
- niveau de difficulté d’un parcours ;
- services proches ;
- photographies réutilisables ;
- date de dernière vérification ;
- éventuellement contenus pour enfants, groupes ou scolaires.

Ces informations sont plus volatiles que les données historiques. Elles devront donc être entretenues séparément.

## Tous les sites ne deviendront pas des lieux touristiques

Il faudra distinguer :

- les sites visitables ;
- les sites seulement visibles ;
- les sites privés à raconter sans inviter à entrer ;
- les sites disparus intégrables à un parcours narratif ;
- les sites trop incertains ou trop sensibles pour être diffusés précisément.

Le projet touristique reposera donc sur une sélection éditoriale, probablement quelques dizaines de lieux ou parcours, et non sur la publication brute de tous les candidats.

## Positionnement possible auprès d’un office de tourisme

Le projet pourrait être présenté ainsi :

> Une carte narrative du patrimoine industriel de l’Orne permettant de découvrir comment les forges, moulins, filatures, mines et ateliers ont façonné les paysages actuels. Le projet associe données historiques vérifiées, cartes, archives et informations pratiques pour proposer des lieux à visiter, des sites à observer et des parcours territoriaux.

L’essentiel est de conserver deux couches :

```text
Socle patrimonial documenté
        ↓
Sélection éditoriale et touristique
        ↓
Parcours, récits, visites et carte publique
```

Ainsi, l’orientation touristique ne déforme pas le travail datajournalistique. Elle devient l’un de ses usages possibles. Le socle actuel permet justement de proposer plus tard une offre touristique sérieuse, différenciante et maintenable.

## Évolution possible

### Première publication

Une expérience datajournalistique relativement simple :

- récit guidé ;
- carte exploratoire ;
- filtres par activité, période et état ;
- fiches documentées des sites ;
- sources et méthodologie.

### Application patrimoniale et touristique

L’utilisateur pourra ensuite choisir plusieurs manières d’entrer dans le projet :

- explorer librement la carte ;
- rechercher un site ou une commune ;
- suivre une histoire thématique ;
- découvrir les lieux proches de sa position ;
- préparer une visite ;
- suivre un parcours ;
- consulter les informations pratiques ;
- enregistrer des lieux ou itinéraires.

Exemple d’organisation :

```text
Accueil
├── Comprendre l’histoire industrielle de l’Orne
├── Explorer la carte
├── Découvrir les sites
├── Suivre un parcours
├── Autour de moi
└── Préparer une visite
```

## La carte reste importante, mais change de rôle

Aujourd’hui, nous parlons de cartographier les sites pour comprendre le territoire.

Dans l’application, la carte pourra servir à :

- montrer la répartition historique ;
- trouver un lieu ;
- visualiser un parcours ;
- découvrir ce qui se trouve à proximité ;
- naviguer entre plusieurs étapes.

Mais un site disparu ou privé pourra être raconté sans forcément devenir une destination proposée au visiteur.

## Deux couches dans une même application

Il faudra distinguer :

### Couche patrimoniale

- histoire ;
- activités successives ;
- bâtiments ;
- archives ;
- objets techniques ;
- sources ;
- précision et incertitudes.

### Couche touristique

- visitabilité ;
- horaires ;
- tarifs ;
- accessibilité ;
- durée de visite ;
- stationnement ;
- contact ;
- parcours associés ;
- date de vérification des informations.

Cette séparation permettra de conserver une base historique rigoureuse tout en proposant une expérience simple au public.

## Le socle actuel prépare déjà cette application

Nos décisions deviennent particulièrement utiles :

- les identifiants stables permettent des URL durables pour chaque site ;
- les géométries permettent la carte et les parcours ;
- les activités successives alimentent les récits historiques ;
- les états actuels indiquent ce qui subsiste ;
- l’accessibilité distingue les lieux visitables des propriétés privées ;
- le versionnement permet de maintenir les informations pratiques ;
- les relations entre sites permettent de construire des itinéraires cohérents ;
- les sources donnent de la crédibilité aux fiches.

## Une dimension importante : l’outil de gestion

Une véritable application touristique aura probablement deux parties :

1. l’application publique ;
2. un espace de gestion permettant d’actualiser horaires, accès, fermetures, parcours et informations pratiques.

Pour un office de tourisme, cette seconde partie peut être aussi importante que la carte publique.

L’orientation générale pourrait donc devenir :

> Un atlas narratif et évolutif du patrimoine industriel de l’Orne, associant exploration historique, cartographie, parcours et préparation de visites.

Notre démarche actuelle reste la bonne : construire d’abord la base patrimoniale fiable, puis développer l’application sur ce socle.

Penses tu que la première publication pourrait être un bon support de présentation pour obtenir de l'accompagnement afin de passer à l'application

Oui. La première publication peut devenir un excellent démonstrateur pour obtenir un accompagnement institutionnel, éditorial ou financier.

Elle devra montrer trois choses :

1. **Le sujet existe**

Prouver que l’Orne possède une histoire industrielle riche et méconnue, avec des lieux, des archives et des récits suffisamment nombreux.

2. **Le projet fonctionne**

Montrer concrètement :

- une carte utilisable ;
- quelques fiches de sites ;
- un parcours narratif ;
- des données vérifiées ;
- des photographies ou archives correctement créditées ;
- une expérience agréable sur ordinateur et mobile.

3. **Le projet peut aller plus loin**

Faire comprendre que le démonstrateur pourrait devenir :

- une application touristique ;
- un atlas départemental ;
- un outil pédagogique ;
- une base pour des circuits de visite ;
- un support pour les communes et offices de tourisme ;
- un projet photographique, historique et culturel plus large.

## Ce que devrait contenir cette première publication

Je viserais une sélection limitée mais convaincante :

- environ 20 à 30 sites ;
- plusieurs secteurs industriels ;
- différentes zones de l’Orne ;
- des sites conservés, disparus et reconvertis ;
- une carte exploratoire ;
- 5 à 10 fiches particulièrement travaillées ;
- 2 ou 3 récits thématiques ;
- éventuellement un premier parcours territorial ;
- une page expliquant la méthode et les perspectives.

Elle ne doit pas chercher à montrer toutes les données disponibles. Elle doit donner envie de financer ou d’accompagner la suite.

## Ce qu’un partenaire pourra évaluer

Avec ce démonstrateur, un office de tourisme ou une collectivité pourra comprendre :

- l’intérêt du sujet pour son territoire ;
- la qualité éditoriale du projet ;
- sa faisabilité technique ;
- les usages touristiques possibles ;
- les besoins en photographie, histoire, design et développement ;
- ce que le partenaire pourrait apporter ;
- ce que deviendrait l’application finale.

## Il faudra accompagner la publication d’un dossier court

La publication seule ne suffira probablement pas. Elle pourra être accompagnée d’un document de présentation contenant :

- le constat de départ ;
- le public visé ;
- le démonstrateur ;
- les usages futurs ;
- les partenaires recherchés ;
- les besoins humains et financiers ;
- une roadmap ;
- plusieurs scénarios de développement.

Par exemple :

```text
Étape 1 — Démonstrateur datajournalistique
Étape 2 — Enrichissement historique et photographique
Étape 3 — Parcours touristiques
Étape 4 — Application publique
Étape 5 — Outil de gestion et actualisation
```

## Le bon positionnement

La première publication ne doit pas être présentée comme une version incomplète de l’application.

Elle peut être présentée comme :

> Une édition pilote démontrant le potentiel éditorial, patrimonial et touristique d’un futur atlas interactif du patrimoine industriel de l’Orne.

C’est beaucoup plus convaincant qu’un dossier théorique : le partenaire peut voir, tester et comprendre immédiatement le projet. Notre approche actuelle — sources vérifiées, modèle structuré, incertitudes documentées — renforce fortement sa crédibilité.
