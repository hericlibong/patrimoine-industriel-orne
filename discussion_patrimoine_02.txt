Voici le **cadrage net** que je te propose.

# 1. Ce qu’on fait

On ne fait pas “une appli patrimoine industriel”.

On fait :

> **une publication interactive datajournalistique qui montre comment les paysages actuels de l’Orne gardent les traces d’une ancienne géographie industrielle.**

Ce n’est pas un inventaire.
Ce n’est pas un dashboard.
Ce n’est pas une appli touristique complète.
Ce n’est pas encore un produit institutionnel.

C’est une **composition interactive publiable**, qui peut ensuite servir de démonstrateur à une rédaction, un office de tourisme, une collectivité ou ton graphiste.

Le document Codex Suggest va dans ce sens quand il parle d’une application narrative et cartographique avec récit guidé, carte libre, fiches de sites, méthode, filtres et couches explicatives. 

# 2. Pourquoi on le fait

Parce que le sujet a une vraie promesse :

> **faire voir une Orne moins évidente : derrière le bocage, les forêts, les vallées, les bourgs et les lieux touristiques, il existe une histoire productive faite de forges, moulins, papeteries, textiles, tuileries, aiguilles, ateliers et sites reconvertis.**

L’intérêt n’est pas de dire :

> “l’Orne était industrielle avant.”

L’intérêt est de dire :

> **“on peut lire autrement l’Orne d’aujourd’hui en retrouvant les traces de ce qu’elle fabriquait.”**

C’est là que le projet devient touristique, historique et data.

# 3. La direction éditoriale

La direction à retenir :

> **Ne pas cartographier le patrimoine industriel pour lui-même.
> Cartographier les traces visibles, invisibles ou disparues d’une ancienne géographie productive.**

Le projet doit répondre à quatre questions simples :

| Question             | Réponse attendue                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------ |
| **Où ?**             | Où étaient les sites industriels dans l’Orne ?                                                   |
| **Quoi ?**           | Quelles activités dominaient : métal, textile, papier, moulins, tuileries, aiguilles ?           |
| **Pourquoi là ?**    | Eau, bois, minerai, vallées, rail, bourgs, ressources locales                                    |
| **Que reste-t-il ?** | Site visitable, bâtiment conservé, trace discrète, reconversion, disparition, friche, site privé |

C’est le squelette du projet. On ne sort pas de ça.

# 4. Ce qu’on ne fait pas

Pour éviter que ça parte dans tous les sens :

| À ne pas faire maintenant                       | Pourquoi                         |
| ----------------------------------------------- | -------------------------------- |
| Cartographier les 2 500 sites potentiels        | trop large, trop sale, trop long |
| Faire un portail exhaustif                      | ce n’est pas le but éditorial    |
| Faire un dashboard                              | froid, peu touristique           |
| Faire une plateforme participative              | trop tôt                         |
| Faire un back-office                            | inutile au départ                |
| Vérifier chaque site sur le terrain             | impossible au départ             |
| Se perdre dans les archives                     | seulement pour 10 à 15 cas forts |
| Faire une application institutionnelle complète | ce sera une phase suivante       |

Codex Suggest dit déjà que le hors-périmètre initial doit exclure les 2 500 sites, le back-office, la plateforme participative, la vérification photographique exhaustive et l’application mobile native. C’est juste. 

# 5. Les données à chercher

On part sur trois familles de données. Pas plus.

## A. Données de corpus

Ce sont les données qui disent : **quels sites existent ?**

Priorité :

| Source                                            | Rôle                                               |
| ------------------------------------------------- | -------------------------------------------------- |
| **Inventaire du patrimoine industriel de l’Orne** | socle principal, probablement les 319 dossiers     |
| **POP / Mérimée**                                 | notices patrimoniales officielles                  |
| **Palissy**                                       | machines, objets, mobilier industriel, quand utile |

But : obtenir une liste propre de sites.

Champs à récupérer :

* nom du site ;
* commune ;
* type de site ;
* activité ;
* période ;
* notice source ;
* résumé historique ;
* coordonnées si disponibles.

## B. Données d’explication

Ce sont les données qui disent : **pourquoi ces sites étaient là ?**

Sources :

| Donnée             | Usage                                    |
| ------------------ | ---------------------------------------- |
| cours d’eau        | moulins, papeteries, énergie hydraulique |
| forêts             | forges, bois, charbon de bois            |
| géologie / minerai | sidérurgie, carrières, tuileries         |
| voies ferrées      | développement, transport, reconversion   |
| limites communales | lecture territoriale                     |
| bourgs / routes    | implantation et accès                    |

But : expliquer la logique du territoire.

## C. Données de devenir

Ce sont les données qui disent : **que reste-t-il ?**

Sources possibles :

| Source                                   | Usage                                 |
| ---------------------------------------- | ------------------------------------- |
| notices Inventaire / Mérimée             | état, description, protection         |
| monuments historiques                    | sites protégés                        |
| offices de tourisme                      | sites visitables ou valorisés         |
| OpenStreetMap / photos / sites officiels | usage actuel, accessibilité apparente |
| vérification manuelle ciblée             | seulement sur 10 à 15 sites           |

But : classer les sites selon leur situation actuelle.

Codex Suggest a raison d’imposer trois dimensions séparées : **conservation**, **usage actuel**, **accès**. Il ne faut surtout pas les mélanger. 

# 6. Le modèle de données minimal

On vise une table simple :

| Colonne                  | Pourquoi                                    |
| ------------------------ | ------------------------------------------- |
| `site_id`                | identifiant interne                         |
| `nom_site`               | affichage                                   |

Pas le code.

# 7. La classification à imposer

Les données brutes vont être bordéliques. Il faut une classification stable.

Je propose 8 familles :

| Famille                            | Exemples                                   |
| ---------------------------------- | ------------------------------------------ |
| **Métal / sidérurgie**             | forge, haut-fourneau, affinerie, fenderie  |
| **Petite métallurgie / précision** | aiguilles, quincaillerie, tréfilerie       |
| **Moulins / agroalimentaire**      | moulin à blé, minoterie, laiterie          |
| **Textile**                        | filature, tissage, teinturerie             |
| **Papier**                         | papeterie, moulin à papier                 |
| **Matériaux**                      | tuilerie, briqueterie, carrière, céramique |
| **Bois**                           | scierie, menuiserie industrielle           |
| **Autres industries**              | chimie, gaz, divers                        |

On ne crée pas 30 catégories.
Sinon la carte devient illisible.

La forme doit être simple :

## Écran 1 — Introduction

But : installer l’idée.

> L’Orne est souvent regardée comme un territoire rural, paysager, touristique. Mais ses vallées, ses forêts, ses bourgs et ses bâtiments conservent aussi les traces d’une histoire industrielle.

## Écran 2 — Carte des sites

But : voir la répartition.

* points par site ;
* couleur par secteur ;
* filtre par secteur ;
* clic vers fiche courte.

## Écran 3 — Pourquoi ici ?

But : expliquer.

* couche cours d’eau ;
* couche forêts ;
* couche rail ;
* éventuellement géologie/minerai.

## Écran 4 — Que reste-t-il ?

But : relier passé et présent.

* conservé ;
* reconverti ;
* disparu ;
* privé ;
* visitable ;
* inconnu.

## Écran 5 — Sites exemples

10 à 15 fiches fortes.

Pas 319 fiches rédigées à la main au départ.

## Écran 6 — Méthode

Sources, limites, incertitudes, données téléchargeables.

# 9. Les outils à utiliser

Je ferais simple et robuste.

| Besoin                  | Outil                                               |
| ----------------------- | --------------------------------------------------- |
| Nettoyage / extraction  | **Python**                                          |
| Données tabulaires      | **CSV** au départ                                   |
| Données géographiques   | **GeoJSON**                                         |
| Analyse spatiale légère | **GeoPandas** si nécessaire                         |
| Carte interactive       | **MapLibre GL JS** ou **Leaflet**                   |
| Interface               | **React + Vite**                                    |
| Visualisations simples  | **D3.js** si besoin                                 |
| Déploiement             | **GitHub Pages** ou **Hugging Face Space statique** |
| Base de données         | pas au départ                                       |

Je ne mettrais pas Django, FastAPI ou PostgreSQL/PostGIS au départ.

Pourquoi ?

Parce que la première publication peut fonctionner avec :

* un `sites.csv` ;
* un `sites.geojson` ;
* quelques fichiers JSON ;
* une interface statique.

C’est plus facile à maintenir, plus rapide à publier, plus compatible avec un projet datajournalistique solo.

PostGIS / API / back-end viendront seulement si le projet devient institutionnel ou collaboratif.
